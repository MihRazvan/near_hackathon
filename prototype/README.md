# Everywhere — product experience prototype

An isolated, local website for reviewing the advertising marketplace before final design. **Everywhere is a working name.** All records, vehicle illustrations, authentication, transactions, AI outputs and analytics are sample values. This app does not connect to wallets or the technical proof server.

Hosted preview: **https://everywhere-near.vercel.app**. Screen index: **https://everywhere-near.vercel.app/_screens**.

```sh
cd prototype
npm ci --ignore-scripts
npm run dev
```

Open **http://localhost:4173**. Production files are generated by `npm run build`. Vite serves only this prototype directory.

The top review bar switches sample personas and populated/empty/loading/error states. **All screens** opens the complete destination index. **Reset** restores the starting story. **Demo controls** advance the sample campaign calendar or save page-specific feedback; the index exports review notes as JSON.

All **63 destinations** in the product map are connected:

- Public marketplace, filters, owner profiles and vehicle pages with selectable surfaces.
- Wallet-only sign-in simulation, buyer campaigns across owners, checkout, payment progress, takeovers, original-payer credits and receipts.
- Owner capture/prompt onboarding, editable surfaces, dated sales, takeover defaults/overrides, public preview and publication.
- Buyer/owner artwork revisions, production lock, installation proof, campaign reporting and earnings held until service/review end.
- Messages, notifications, profiles, wallet settings, support, operator review and payment-recovery views.

Start at **http://localhost:4173/_screens** to review the whole map, or follow a story:

1. Choose **Lena** in the review bar, explore a vehicle and book an available spot. The simulated payment has source-payment and purchase-authorization steps.
2. Choose **Otto** and take over the Alpine Electric left door. Switch back to Lena to inspect and claim her original-wallet credit.
3. Choose **Mara**, create an asset from a description or photo, edit its surfaces and publish a sale. Review buyer artwork from Bookings.
4. Open **Demo controls** on a booking or sale and choose its stage. This lets you inspect production, installation proof, issue review and eligible payouts without waiting for calendar dates.
5. Choose **Alex** to inspect operator queues, support decisions and audit history.

**Mobile:** the selected-spot bar opens a bottom sheet with its price, dates and booking action. Owner capture has a dedicated phone preview. The decorative QR is explicitly a placeholder; its adjacent phone link works. Surface editing supports drag/resize and a list/property editor; it uses rectangular illustrative surfaces rather than production wrap geometry.

**Feedback:** Demo controls → Leave a note records the page ID, URL and your comment. Export notes from All screens to share the JSON with the team. Draft form values and business-state changes persist locally; Reset removes the sample changes.

## Verification

```sh
npm test
npm run build
```

Browser checks use the `playwright-cli` skill/tool from the repository root while the dev server runs:

```sh
playwright-cli -s=everywhere open http://127.0.0.1:4173
playwright-cli -s=everywhere --raw run-code --filename=prototype/tests/browser-review.js
playwright-cli -s=everywhere --raw run-code --filename=prototype/tests/browser-flows.js
```

The scripts use the origin of the page opened in the browser, so the same checks can run against the hosted preview. The first script visits all 63 destinations at desktop and mobile widths, checking headings, JavaScript errors, unfinished scaffolds, horizontal overflow and external requests. The second walks asset creation/publication, buyer authentication/payment recovery, creative revisions, installation proof, held earnings, payout, takeover/credits and operator review. Browser screenshots go to ignored `prototype/artifacts/`.

This is a design-review prototype. Authentication and financial transitions are local simulations, phone capture is a browser handoff preview, AI generation uses an editable illustration, and reports contain sample values. It has no real service/API integration or multi-user backend. Exported notes are local files; they are not sent to another person automatically. A teammate can clone the pushed repository, run the commands above and review the same starting story.

The complete screen inventory is available at `/_screens`. The review-window duration in sample dates is illustrative; it is not an agreed commercial policy.

## Vercel

Deploy from the repository root. The root `vercel.json` installs and builds this directory, serves `prototype/dist`, and rewrites deep links to the app entry point. `.vercelignore` limits CLI uploads to website build inputs. No environment variables or wallet keys are needed.

```sh
vercel deploy --prod
```
